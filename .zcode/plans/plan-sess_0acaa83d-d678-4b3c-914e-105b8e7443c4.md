## ภาพรวม

4 งาน: (1) ซ่อนชื่อผู้ให้บริการจากหน้า user, (2) รวม /admin/models เข้ากับ Routing เป็นหน้าเดียว, (3) หลาย API key ต่อ provider + หมุนอัตโนมัติ, (4) คลังรูปโลโก้บน Supabase Storage ที่อัปครั้งเดียวใช้ซ้ำได้ (ผูกกับโมเดล)

**ข้อจำกัดที่ต้องบอกก่อน (สำคัญ):** ตอนนี้ระบบยังไม่มี API gateway endpoint จริงสำหรับให้ลูกค้ายิง request (มีแค่ UI) ดังนั้น "หมุนคีย์อัตโนมัติเมื่อ error" จะทำเป็น **engine + UI สุขภาพคีย์** ที่พร้อมถูกเรียก — ยังไม่มีจุด runtime จริงให้ต่อ ผมจะทำเป็นฟังก์ชันที่เทสได้และมีที่บันทึกสถิติ รอ gateway มาต่อยอด

## ระยะ 1 — Schema + DB

**`src/db/schema.ts`** เพิ่ม 2 ตาราง + 1 คอลัมน์

```ts
// คีย์หลายอันต่อ provider + สถิติสำหรับหมุนอัตโนมัติ
export const providerKeys = pgTable("provider_keys", {
  id: serial("id").primaryKey(),
  providerId: integer("provider_id").notNull()
    .references(() => providers.id, { onDelete: "cascade" }),
  label: text("label").notNull().default(""),      // "main" / "backup-1"
  apiKey: text("api_key").notNull().default(""),
  enabled: boolean("enabled").notNull().default(true),
  isPrimary: boolean("is_primary").notNull().default(false),
  // สถิติสำหรับหมุน
  failureCount: integer("failure_count").notNull().default(0),
  cooldownUntil: timestamp("cooldown_until", { withTimezone: true }),
  lastErrorAt: timestamp("last_error_at", { withTimezone: true }),
  lastUsedAt: timestamp("last_used_at", { withTimezone: true }),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
});

// คลังรูปที่อัปโหลดแล้ว — ใช้ซ้ำได้ ไม่ต้องอัปซ้ำ
export const assets = pgTable("assets", {
  id: serial("id").primaryKey(),
  name: text("name").notNull().default(""),        // ชื่อในคลัง เช่น "OpenAI"
  storagePath: text("storage_path").notNull(),     // path ใน bucket
  publicUrl: text("public_url").notNull(),
  mimeType: text("mime_type").notNull().default(""),
  sizeBytes: integer("size_bytes").notNull().default(0),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
});
```

+ `models.logoUrl: text("logo_url")` (nullable)

**การย้ายข้อมูลคีย์เดิม:** `providers.apiKey` จะเลิกใช้ (mark deprecated ใน comment แต่**ไม่ลบ column** เพื่อกันข้อมูลหาย) — migration จะคัดค่าที่มีอยู่เข้า `provider_keys` เป็น is_primary ทีละตัว

**ไฟล์ที่แตะ:** `src/db/schema.ts`, migration ใหม่ผ่าน `npm run db:generate` → `db:push`, ต่อท้าย `supabase/setup.sql` (idempotent) สำหรับสาย Dashboard, แก้ `src/db/seed.ts` (seed 2 คีย์ให้ OpenAI เพื่อโชว์การหมุน), `src/lib/demo/store.ts` (เพิ่ม `providerKeys`/`assets` + `logoUrl` ใน seed)

## ระยะ 2 — Supabase Storage + คลังรูป

1. **`src/lib/supabase/admin.ts`** (ใหม่) — service-role client ใช้ `SUPABASE_SERVICE_ROLE_KEY` ที่มีใน env แล้วแต่ยังไม่มีโค้ดใช้ (เดิมคีย์นี้ไม่ถูกใช้เลย) ใส่ `import "server-only"` กันหลุดไป client
2. **`src/db/setup-storage.ts`** (ใหม่) + npm script `storage:setup` — สร้าง bucket `octopus-assets` (public read) แบบ idempotent → ไม่ต้องกดมือใน Dashboard
3. **`next.config.mjs`** — เพิ่ม `images.remotePatterns` สำหรับ `**.supabase.co` (เดิมไม่มี ทำให้ next/image  render URL ภายนอกไม่ได้)
4. **`src/lib/data/admin.ts`** — `listAssets()`, `createAsset()`, `deleteAsset()`, `setModelLogo(modelId, url)`

**ความปลอดภัยของไฟล์อัปโหลด (ตัดสินใจไว้):** รับเฉพาะ `png/jpg/jpeg/webp` และจำกัด 2MB — **ไม่รับ SVG** เพราะ SVG ฝังสคริปต์ได้ (XSS) และจะตั้งชื่อไฟล์ใหม่แบบสุ่ม ไม่ใช้ชื่อจากผู้ใช้

## ระยะ 3 — หลาย API key + engine หมุน

**`src/lib/rotation.ts`** (ใหม่) — ฟังก์ชันบริสุทธิ์ เทสได้ ไม่พึ่ง DB
```
pickKey(keys, now): เลือก enabled && ไม่อยู่ใน cooldown
  เรียง: isPrimary ก่อน → lastUsedAt เก่าสุด (ยังไม่เคยใช้มาก่อน) → failureCount น้อยสุด
backoffMs(failureCount): 30s → 2m → 10m → 30m (มีเพดาน)
```
**`src/lib/data/admin.ts`** — `listProviderKeys`, `addProviderKey`, `updateProviderKey`, `deleteProviderKey`, `setPrimaryKey`, และ `recordKeyResult(keyId, ok, kind)` (ok → reset failureCount/cooldown + อัปเดต lastUsedAt; error/rate_limit → failureCount++ + ตั้ง cooldownUntil)

**UI ในหน้า Providers** — แต่ละ provider มีรายการคีย์: เพิ่ม/ลบ/แก้, ป้าย "คีย์หลัก", toggle เปิด/ปิด, แสดงสถานะสุขภาพ (จำนวนพลาด, cooldown เหลืออีกกี่นาที) — แทนช่อง API Key เดี่ยวเดิม

## ระยะ 4 — รวมหน้า admin + ซ่อน provider ฝั่ง user

**รวมเป็นหน้าเดียว** — ย้ายทุกอย่างจาก `/admin/models` (ราคา, เปิด/ปิด, แสดงผู้ใช้) เข้า `/admin/routes` แล้ว**ลบโฟลเดอร์ `src/app/(app)/admin/models/`** และตัดเมนู "โมเดลที่แสดง" ออก (เหลือ "Routing & Models")

หน้าเดียวนี้จะเป็น "combo" จริง ๆ ตามที่ขอ:
- **ส่วนโมเดล** — ตารางทุกโมเดล ข้าม provider: enable, visible, ราคา in/out, context, vision, **รูปโลโก้ (อัปใหม่/เลือกจากคลัง)**
- **ส่วน route** — primary + fallback: `<select>` เปลี่ยนเป็น **`<optgroup>` แยกตาม provider** เพื่อให้เห็นชัดว่า "โมเดลอื่นใน provider เดียวกัน" กับ "จาก provider อื่น" อยู่ที่เดียวกัน (เดิมเป็นลิสต์แบน)
- รวมเป็นหน้าเดียว = แก้ที่เดียวจบ ไม่ต้องสลับ 2 หน้า

**หน้า user `/models`** — เอา**คอลัมน์ "ผู้ให้บริการ" ออก** ตามที่ขอ เอา logo มาแทนตำแหน่งนั้น (ให้ยังเห็นอัตลักษณ์แบรนด์โดยไม่ต้องบอกชื่อค่าย) และแก้ badge จาก "{a} โมเดล · {b} provider" → เหลือจำนวนโมเดล

**ไฟล์ที่แตะ:** `admin/routes/page.tsx` (รวม), ลบ `admin/models/page.tsx`, `(app)/layout.tsx` (เมนู), `admin/page.tsx:33` (ลิงก์), `models/page.tsx` (ผู้ใช้), `dashboard/page.tsx:160` (ข้อความอ้างอิง), `admin/actions.ts` (action ใหม่ + revalidate)

## ระยะ 5 — ตรวจรับ

- `npm run db:generate` → `db:push` → `db:seed` → `npm run storage:setup`
- `npx tsc --noEmit` + `npm run build` ผ่าน
- เปิดเบราว์เซอร์จริงตรวจ: หน้า Providers (หลายคีย์), หน้า Routing & Models (รวม + optgroup + อัปโหลดรูป), หน้า /models ฝั่ง user (ไม่มีชื่อ provider, มีโลโก้)
- เพิ่มคําแปล i18n ของข้อความใหม่ใน `dictionaries/admin.ts` + `app.ts` (ระบบใช้ไทยเป็นคีย์, คีย์ที่ไม่มีจะ fallback เป็นไทยเสมอ ไม่พัง)

## หมายเหตุ
- ถ้าต้องการให้**โลโก้แสดงเฉพาะ admin** (ไม่โชว์หน้า user) บอกได้ ผมปรับจุดเดียว
- `providers.apiKey` จะไม่ถูกลบ เพื่อกันข้อมูลเดิมหาย แต่จะไม่ถูกใช้ในโค้ดอีก
